# disaster-alert-sample

防災情報の自動配信システムのサンプルコードです。

実案件のソースコードは非公開のため、実績紹介用に、処理の流れ（情報の取り込み → 条件判定 → 配信文の生成 → 複数チャネルへの配信）を小さく再現したサンプルを公開しています。

## 処理の流れ

1. **取り込み**：地震情報のフィード（サンプルではJSON形式）を読み込む
2. **検証**：必須項目の欠けや型の誤りがあるデータは配信せずにスキップする
3. **条件判定**：最大震度などの条件で、配信対象かどうかを判定する
4. **整形**：配信先で読みやすい定型文に整形する
5. **配信**：登録された配信チャネル（サンプルではコンソール出力・ログファイル・Webhook）へ送る

実案件では、気象庁の防災情報XMLをWebSocketで受信し、LINEやDiscordなど複数サービスへ24時間体制で配信しています。このサンプルはその簡易再現です。

## 止まらないための工夫

- 1つのチャネルで配信に失敗しても、ほかのチャネルや後続の情報の配信は続ける
- Webhook は一時的な失敗（5xx・接続エラー）なら最大3回まで再試行する。4xx は送り直しても結果が変わらないため再試行しない
- 同じ内容の情報が重複して届いても二重に配信しない。内容が更新された続報は配信する
- 不正なデータが1件混ざっても、処理全体は止めない

## 実行方法

```bash
python3 alert_delivery.py
```

`sample_feed.json` の地震情報のうち、最大震度5弱以上（数値 5.0 以上）のものだけが配信対象として処理され、整形された配信文が表示され、`delivery_log.txt` に記録されます。

環境変数 `ALERT_WEBHOOK_URL` に http(s) のURLを設定すると、そのURLへJSON（`{"text": "配信文"}`）でPOSTします。未設定のときは送信しません。

## テスト

```bash
python3 -m unittest -v
```

震度の判定、配信文の整形、不正データのスキップ、重複の排除と続報の配信、チャネル障害時の継続、Webhook の再試行（テスト用のローカルサーバーを使用）などを確認する15本のテストがあります。

## 備考

- サンプル内の地震情報はすべて架空のものです。
- 使用技術：Python 3.11 以上（標準ライブラリのみ、追加インストール不要）
